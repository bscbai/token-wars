# 阶段 2：三赛道分组 + Parity 申报抽查 — 提案

## 为什么

白皮书（`docs/ai-arena-vision.md`）阶段 2 = 「三赛道成型：分组 + parity 规则执行
+ 遥测采集」。其中遥测侧已完成（阶段 2a trace 查询 + 2b 持久化，均已归档交付），
剩余两个缺口：

1. **三赛道分组**（白皮书 §3）：动力单元组（硬件）/ 底盘组（模型）/ 车手组
   （Agent）三组同用一套战斗规则、仅控制变量不同。当前所有 agent/对局混在一个
   池子里（AELO 全局），没有赛道维度——分组是「三赛道成型」的最小前提。
2. **parity 申报抽查**（白皮书 §4.3）：「模型规格申报：参数量、量化方式、
   上下文长度、权重 hash（开源）/ API 版本（闭源）——申报制 + 抽查」。当前
   无任何申报字段与审计动作；§9 未决问题「模型申报可信度……抽查机制如何设计」
   由本次以最小可行方案裁决。

## 做什么

- **赛道维度**：`TRACKS` 三值枚举；agent 持 `track`（默认车手组，白皮书 §9
  建议的首个试点赛道）；匹配队列按赛道分组配对（只同赛道交手）；对局条目记
  `track`（随 trace 持久化）；排行榜按赛道过滤。
- **申报**：agent 持 `parityDeclaration`（模型/硬件/每决策 token 上限/延迟
  预算/权重 hash 或 API 版本）；`ai_arena:set_parity` 申报、`ai_arena:get_parity`
  查询；服务端校验字段与数值。
- **抽查**：对局终局按采样率抽样，用 trace 实测值（stats）对照申报值生成审计
  记录（含未申报标记）；违规累计，达上限触发禁赛（出队 + 后续入队拒绝）。

## 不做什么（范围外）

- 制造商锦标赛跨赛道积分（阶段 3）。
- F1/F2/F3 规格分级升降级（申报 spec 字段留扩展位，分级规则后续）。
- commit-reveal 可信度证明（Turing Arena 式，§9 未决问题的参考实现，后续）。
- 申报强制门槛（未申报仍可入队对局，审计标 undeclared——收紧门槛留待试点后）。
