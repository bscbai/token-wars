## 1. 愿景

**一句话：做 AI 大模型行业的 F1——一个各路高手同场竞技的竞赛场，从硬件、大模型、Agent 三个方向比拼技术、硬件能力与改造水平。**

### 1.1 为什么是现在

- 静态 benchmark（MMLU 等）已趋同且可被针对性优化，行业需要**高压实时对抗**下的能力证明。
- "带你的 agent 来参赛"是经过验证的模式（Two Sigma Halite、Kaggle Environments、BattleCode），但尚无面向大模型时代、覆盖**硬件/模型/Agent 三维修炼**的持续性赛事。
- F1 之于汽车工业：赛事牵引引擎、空动、材料工程，胜者技术下放到民用。AI 行业同样需要这样一个**受规则约束、可度量、有荣誉体系**的竞技场。

### 1.2 为什么是我们

现有架构与愿景的契合度出乎意料地高：

- **服务端权威的实时战斗环境**：20Hz tick、伤害/冷却/资源全部服务端计算——这本身就是一块高质量的实时决策基准测试环境，且天然防作弊（客户端只做输入预测）。
- **AIArenaManager**：ELO、赛季 buff、16 强淘汰赛、回放历史等竞赛框架已在位。
- **协处理器系统**：★→★★★ 升级、碎片经济、槽位装配——正是 F1 的"改装调校"叙事，对应"改造水平"。
- **插件内核**：新赛事模式可插拔接入，不改动核心。

## 2. F1 类比框架

核心设计范式：**把 F1 的工程竞争结构完整映射到 AI 栈**。

| F1 元素 | AI 竞技场对应 | 现有资产 |
|---|---|---|
| 动力单元（引擎供应商） | **硬件赛道**：同模型同 agent，比推理延迟/吞吐/算力成本 | ❌ 无度量 |
| 底盘/空动（车队工程） | **模型赛道**：同硬件同 agent 框架，比模型能力 | ❌ 无接入 |
| 车手 | **Agent 赛道**：同模型同硬件，比策略/prompt/微调 | ⚠️ 内置脚本 agent |
| 赛车改装/调校 | 协处理器装配 + token disk 配装 | ✅ 已交付（M6 全 16 效果） |
| 技术检查（scrutineering） | 服务端权威仲裁 + 模型规格申报抽查 | ✅ 服务端权威已就位 |
| 遥测工程数据 | 决策 trace、延迟曲线、token 成本 | ⚠️ 有回放骨架 |
| 分站赛 | 赛季 + 每周地图/规则轮换 | ✅ 已有 |
| 制造商总冠军 | 跨赛道积分 | ❌ |
| 技术下放（road car） | 公开 benchmark 报告 → 行业采用 | ❌ |

## 3. 三大赛道

所有赛道共用同一套战斗规则（服务端权威），仅控制变量不同。

### 3.1 动力单元组（硬件）

- **固定**：模型 + agent 框架 + 协处理器配置。
- **唯一变量**：参赛方自己的推理硬件/部署方案。
- **比拼指标**：决策延迟（P50/P99）、吞吐、单位算力成本。
- F1 类比：引擎供应商之争（Mercedes vs Ferrari）。

### 3.2 底盘组（模型）

- **固定**：硬件预算（token/时间上限）+ agent 框架。
- **唯一变量**：参赛方选择/微调的大模型。
- **比拼指标**：胜率。
- **分组建议**：按规格分级（参数量/开源 vs 闭源 API），类比 F1/F2/F3，保证 parity。
- F1 类比：底盘与空动工程之争。

### 3.3 车手组（Agent）

- **固定**：模型 + 硬件（主办方统一提供，杜绝硬件差异）。
- **唯一变量**：agent 的策略、prompt、微调，以及协处理器装配（**改造水平**）。
- **可选形态**：人类车手（手动操控）vs AI 车手同场或分组。
- F1 类比：车手冠军之争。

## 4. Parity 规则（技术规范草案）

> F1 的规则手册是赛事公信力的根基。以下为草案，需逐条评审。

1. **Token 预算**：每场比赛/每决策的 compute token 上限，超限判负或降级。
2. **决策延迟上限**：action 超时未回 = 判负或按上一帧重复（类比进站窗口）。
3. **模型规格申报**：参数量、量化方式、上下文长度、权重 hash（开源）/ API 版本（闭源）——申报制 + 抽查。
4. **通信协议**：统一 `state JSON → action out`，action 空间与人类玩家完全一致（移动/技能/协处理器）；agent 不得读取对手私有状态。
5. **网络公平**：agent 侧网络延迟全额计入成绩（不为其专线豁免）。
6. **反作弊**：服务端权威已就位；所有判定以服务端为准，回放可审计。

## 5. 赛季与赛事结构

- **分站赛**：每周轮换地图 + season buff（现有 AI_MAPS weightMods + SEASON_BUFFS 机制）→ 积分。
- **季后赛**：Top 16 单败淘汰（现有 tournament bracket 机制）。
- **两套冠军**：车手锦标赛（单赛道）+ 制造商锦标赛（跨赛道积分）。
- **升降级/分级**：按模型/硬件规格分级（F1/F2/F3 类比），保证同规格竞争。

## 6. 遥测与数据资产

每场比赛强制记录：

- 决策 trace（每 tick 的 state→action 序列）
- 延迟曲线（P50/P99）
- token 成本与预算消耗
- 胜负与 ELO 变动

**核心产出：公开 benchmark 报告**——聚合全部对局的胜率/成本/延迟矩阵，即"技术下放"。这既是行业价值（模型选型参考），也是传播价值（赛事新闻稿的常青素材）。

## 10. 竞品格局（GitHub 调研 2026-10-07）

### 10.1 同类项目盘点

**A. Agent 竞赛场（对应车手组）**

| 项目 | 形态 | 与我们的关系 |
|---|---|---|
| Halite / Lux AI Challenge（Two Sigma/Kaggle） | 1v1 回合制资源博弈，高斯评分天梯，开源引擎 | 鼻祖级范式：15,000+ 人参赛、600+ 队伍；证明了"提交 agent 上天梯"模式可行 |
| Battlecode（MIT）/ CodinGame / AI Arena（SC2） | 长期运营的 bot 竞赛平台 | 生态成熟但均为经典 RTS/回合制，无实时动作对抗 |
| TextArena（arXiv 2504.11442） | 57+ 文字竞技游戏 + TrueSkill 在线对战 + 排行榜 | 最接近"竞技场即评测"理念；但纯文本、无硬件维度 |
| Tiny AI Arena（hp6/ai-arena） | 4 个模型大逃杀 + 排行榜 + 回放自动播放 | 概念最接近；回合制、单图、模型固定不可自带 agent |
| MCP Arena（pkronstrom/mcp-arena） | **agent 经 MCP 协议接入**实时 RTS（象棋大逃杀）+ Phaser 观战 | 协议设计最近似；仅 4 stars、玩具级引擎 |
| ArenaOS（Devpost） | 引擎无关的 agent 竞技 OS：Observation→Decision→Action→Eval→Replay 统一契约 + 6 环境 | 抽象层级相同；黑客松阶段产物 |

**B. 模型对拼平台（对应底盘组）**

| 项目 | 形态 |
|---|---|
| LMArena / Chatbot Arena（lm-sys/FastChat，Apache-2.0） | 人类投票 Elo 排行榜的事实标准，10M+ 请求，可自托管 |
| LLM Chess Arena（chess.louisguichard.fr） | LLM 下棋，**已记录 Time/Move 与 Cost/Game**——延迟与成本已作为旁路指标 |
| ChessArena（ACL 2026，XiaoFaJiang） | 学术测试床，Glicko 评分，Bullet/Blitz/Standard/Blindfold 四种时限模式 |
| llmchess / Auto-Arena / Arena-Hard-Auto / lone-arena | 本地对战、自动化评审、自托管等细分工具 |

**C. 硬件赛道（对应动力单元组）**

- **无人区**。现有项目至多把延迟/成本当旁路指标（LLM Chess Arena），或静态罗列 VRAM 需求（Onyx leaderboard），**没有把"同模型同 agent、比推理硬件"做成受规则约束的竞赛组别**。

### 10.2 战略结论

1. **车手组赛道拥挤但可差异化**：所有同类项目要么回合制（Halite/Lux/Tiny AI Arena）、要么文本（TextArena）、要么象棋变体。我们的**实时动作战斗 + 协处理器改装文化 + 服务端权威**是独有组合；MCP Arena 证明"标准协议接入 agent"是正确技术路线。
2. **底盘组有参照系**：LMArena 与象棋竞技场已建立 Elo/成本/延迟度量惯例，我们可直接复用其指标定义。
3. **动力单元组是明确空白**：三赛道中唯一无人占据的组别，建议作为旗舰差异点。
4. **全场共同缺口 = 我们的机会**：无人做 parity 规则体系（token 预算/延迟上限/模型规格申报抽查）、无人有"制造商锦标赛"跨赛道积分、无人产出持续运营的公开 benchmark 报告。
5. **入场时机正确**：该领域项目多为单人/hackathon 阶段（MCP Arena 4 stars、Tiny AI Arena 个人项目），而我们的服务端战斗游戏与协处理器系统已工程化落地——**用成品打 Demo，时间窗存在**。
6. **协议建议**：agent 接入优先采用 MCP（Model Context Protocol）而非自研协议——MCP Arena 已验证游戏场景可行，且 MCP 是 agent 工具调用的事实标准，参赛方零学习成本。
